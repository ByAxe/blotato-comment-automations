# Product context

Blotato documents comment-to-DM campaigns for Instagram professional accounts and Facebook Pages. The pricing workflow in this repository models one such campaign for standard Instagram feed posts. The comparison uses public Blotato documentation checked on 24 November 2026. [Blotato DM Automations](https://help.blotato.com/web-app-features/dm-automations) · [Supported account types](https://www.blotato.com/blog/dm-automation-api#how-blotato-models-an-automation) · [Project requirements](requirements.md)

| --- | --- | --- |
| Trigger | A rule can watch all posts and reels on the connected account or one post identified by its Blotato tracking ID. Top-level comments on owned posts qualify. Keywords match case-insensitively anywhere in the text, and an empty list matches any eligible comment. An inbound DM can also start a run. | Rules and overlap | More than one automation can be live on an account. Each matching automation starts a run. For two matches on the same comment, both runs attempt to send. ## Engineering implications

- **Post identity and overlap.** The adapter supplies the verified Instagram media ID at intake. Missing post identity can match an account-wide version. A post-scoped version ignores it and records the event identity for deduplication. Supporting multiple rules would require an explicit decision about which runs may enqueue sends. The provider grants one initial private reply per comment across tools and rules. Keep the source comment identity and the active conversation identity distinct. [Instagram integration contract](integration.md#instagram-pricing-flow) · [Blotato platform rules](https://help.blotato.com/rest-api-reference/dm-automations#platform-rules)
- **Admission and deadlines.** Blotato's published monthly limits are 1,000, 6,000 and 15,000 active contacts for Starter, Creator and Agency, with custom limits on some accounts. A public reply or DM can count toward usage. Repeated replies to the same person on the same connected account in the month count once. Reaching a new contact above the cap can fail the run. An equivalent quota would need to account for concurrent first sends and uncertain outcomes. Budget that separately from provider throttling and send deadlines. [Plan limits and active contacts](https://help.blotato.com/settings/billing-and-credits#active-contacts) · [Messaging windows](https://help.blotato.com/rest-api-reference/messages#messaging-windows)
- **Send settlement.** Blotato's messaging API returns `queued` with a message ID and directs clients to poll for `sent` or `failed`. Runs expose failures such as expired authorization, closed messaging windows and rejected private replies. An adapter using this API would track the message ID and settle only after a terminal status. The local contract distinguishes a confirmed non-send from an uncertain result. [Send Message](https://help.blotato.com/rest-api-reference/messages#send-message) · [Blotato error reference](https://help.blotato.com/support/errors#dm-automation-errors) · [Local provider contract](api.md#fake-provider)
- **Burst workload.** Model a hot account with concurrent intake and delivery, provider latency and throttling. Measure queue age, remaining send-window time and progress for other accounts during the burst. Blotato documents public API limits of 30 requests per minute for each send or automation mutation route and 60 for each corresponding read route. Size runtime processing against measurements from the target integration. [Blotato API rate limits](https://help.blotato.com/api-and-mcp-concepts/rate-limits) · [Local capacity model and measurements](capacity.md)

The repository's executable evidence covers synthetic events, local PostgreSQL, and a recording provider. Live provider acceptance, message delivery, API quotas, and production capacity require evidence from the target environment. The public references describe customer-visible behavior. Blotato's internal topology and traffic volumes are outside the scope of this comparison.
