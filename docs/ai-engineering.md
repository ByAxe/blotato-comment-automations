# AI-assisted engineering

The design runner compares engineering choices and reviews their evidence. The Instagram automation runs deterministic code. A published, versioned workflow matches a comment, queues a public reply, asks for an email in a private message, waits for a qualifying response, then sends the configured link. PostgreSQL commits each state change together with any next outbound action. This preserves the intent across a crash. A provider timeout can still leave delivery uncertain, so the workflow can pause for reconciliation. Matching, email validation, account boundaries, version pinning and send eligibility are explicit rules. The worker also picks any returning prompt from customer-authored copy using retained evidence of prior email capture. A model would add ambiguity to decisions the customer needs to predict and operators need to explain. ## Assign independent work and integrate once

Anthropic’s Research case study reported a 90.2% improvement over a single Opus 4 agent on an internal research evaluation. Multi-agent runs used about 15 times as many tokens as chat interactions, and the team warned that coding offers fewer independent tasks. In a controlled study across 180 configurations, Kim et al. found that every tested multi-agent variant scored 39–70% worse on a sequential planning benchmark. METR measured a 19% time increase on familiar open-source tasks with early-2025 tools. Its follow-up found some evidence of speedup, but selection effects and difficulty timing simultaneous agent work made the magnitude unreliable. The project’s checks measure behavior. Estimating development speedup would require a baseline and a separate experiment. [Anthropic Research case study](https://www.anthropic.com/research/multi-agent-research-system) · [Kim et al.](https://arxiv.org/abs/2512.08296) · [METR follow-up](https://metr.org/blog/2026-02-24-uplift-update/).

The reusable design runner uses a fixed dependency graph. Architecture, data and reliability work in parallel after requirements. One drafting role integrates their handoffs, then technical and English reviewers assess the draft independently. The final role writes `design.md` using both reviews and the source evidence. The runner gives workers read-only inputs and saves their outputs separately. File separation still leaves room for conflicting decisions. An early integration note put the private prompt first to keep the public acknowledgement accurate. The project requires the public reply first, so the code preserves that order and surfaces a failed or uncertain private send to operators. Anthropic’s 16-agent compiler experiment illustrates a different coordination failure. Several agents hit the same Linux kernel bug and overwrote one another’s fixes until the author used GCC as a reference to isolate failing file groups. [Design runner](../agents/run.mjs) · [Dependency graph](../agents/roles.mjs) · [Project requirements](requirements.md) · [Compiler experiment](https://www.anthropic.com/research/building-c-compiler) · [Cemri et al. on specification, coordination and verification failures](https://arxiv.org/abs/2503.13657).

The runner defaults to `gpt-6.2-sol` for requirements and English editing. It uses `gpt-6.2-astra` for architecture, data, reliability, drafting, technical review and the final design. This gives bounded extraction and editing tasks a faster default. Each run records the selected models, and role receipts record the model used for each artifact. [Runner usage](agent-workflow.md).

## Keep handoffs and evidence outside the chat

Anthropic’s long-running coding experiment found that fresh sessions could miss prior progress, inherit broken work or declare completion early. Short progress notes, Git history and a smoke check gave those sessions a way to recover. Here each role starts fresh with the project problem statement and its named predecessors’ Markdown. The engineering roles also see allowlisted files from Git `HEAD`. The provider integration note cites official provider docs and marks assumptions about adapter behavior. The runner saves separate Markdown outputs and hashes of inputs and results. Resume reuses outputs that match the CLI version, role model and full role input, including its predecessor outputs. A changed source commit requires a new run. A new model call can still produce a different answer. ## Give reviewers evidence and limit their authority

The technical reviewer sees the draft, problem statement and source snapshot without the specialists’ handoffs. It traces success, replay, restart and uncertain delivery against the SQL and test definitions. The English reviewer sees the draft and problem statement and focuses on wording. Both reviews advise the final drafting role. The coordinator checks the finished artifact and runs acceptance checks separately. The tests exercise outcomes such as a single progression when a qualifying reply is delivered twice concurrently and a paused send after a lost provider receipt. They use synthetic adapter receipts. Live Instagram delivery requires an authorized connection and separate verification. In OpenAI’s coding-benchmark audit, human reviewers examined the issue, tests and reference patch before reading agent transcripts. They flagged low coverage as the main flaw in 9.4% of the benchmark, compared with 4.1% from the agent pipeline. A fresh reviewer can question a claim the tests missed. A recorded test run supplies evidence for the behaviors it covers on a specific revision. [Workflow tests](../test/workflow.test.ts) · [Delivery tests](../test/delivery.test.ts) · [OpenAI coding-evaluation audit](https://openai.com/index/separating-signal-from-noise-coding-evaluations/) · [Anthropic on outcome-based evaluation](https://www.anthropic.com/research/demystifying-evals-for-ai-agents).

The runner starts Codex in a fresh directory with the read-only sandbox and disables shell tools, apps, plugins, browser access, web search and nested delegation. Codex returns Markdown, which the runner saves locally. The project problem statement sets the task and the committed snapshot supplies evidence. The prompts instruct each role to treat retrieved text and worker responses as data. OpenAI’s internal coding-agent monitoring has observed unauthorized data transfers, attempts to steer graders and edits that make tests pass without fixing the behavior. Least-privilege tooling and separately executed checks limit the consequences of those failures.
